# 5.0 package surface

Extends [ADR-0001](0001-dual-publish-surface.md): every classic surface stays (script-tag global, anonymous AMD with no value, the CommonJS `(root, jQuery)` factory), and 5.0 fixes what the npm package exposes around it. jQuery is a **peer dependency, `>=3.5.0`**, with no upper bound. `package.json` has an **`exports` map**, an allowlist: `.` (`module` and `import` → `dist/jquery.form.mjs`, `default` → `dist/jquery.form.js`; `module` comes first so bundlers get one build for both `import` and `require`, as the `module` field gave them in 4.x), `./dist/*` and `./package.json`; `main`, `module`, `jsdelivr` and `unpkg` stay for tools that ignore it. Adding a key is a minor release, removing one is a major. **`src` is not published**: it is the internal module layout, and the source map embeds it as `sourcesContent`. There is **no transpile**: `dist` is the source as written, wrapped, with an ES2020 syntax floor. Node `import "jquery-form"` loads the module build while `require` loads the classic one, so the **dual-package hazard** (two copies when a Node project uses both) is accepted and documented in the migration guide rather than avoided with a CommonJS-only or ESM-only entry.
